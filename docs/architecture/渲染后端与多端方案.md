# 渲染后端与多端方案

mensic 的绘图不是「用 JS 重画一遍」，而是**真的跑 matplotlib**：每个案例自带 `chart.py`，
渲染器把 `chart.py` + 数据 + 参数跑成 PNG/SVG。导出的 `run.py` 内联同一段渲染逻辑，
因此「界面预览 = 导出脚本」。这个硬约束决定了整套渲染架构。

## 后端注册表与降级链

上层只依赖一个窄契约（`src/renderers/types.ts`）：

```ts
interface Renderer {
  renderPng(spec): Promise<{ png: Uint8Array; ms: number }>;
  renderSvg(spec): Promise<{ svg: string; ms: number }>;
  caseScript(spec): Promise<string>;       // run.py 文本
  packageZip(spec): Promise<Uint8Array>;   // 可运行包
  warmup(): Promise<void>;                 // 后台预热
}
```

`src/renderers/registry.ts` 在运行期挑选实现，并按两类原因降级：

| 情况 | 行为 |
|---|---|
| 本端原生在真实渲染中报错 | **永久降级**到 Pyodide（本次会话不再尝试原生），应用保持可用 |
| 案例需要本端未随包的依赖（如 scipy） | **单次**改用 Pyodide（会按需安装该包），不降级 |

```
本端原生（Tauri 桌面 sidecar） ──失败→ Pyodide（Web / 移动端 / 兜底）
```

移动端（Android/iOS）没有随包 Python，`isNativeSupported()` 会直接跳过原生探测。

**渲染输入是内容自包含的**：spec 里带的是 `chartSource` / `tokensSource` 的**源码文本**，
不是 URL。因此任何后端（含未来的云端）都不需要理解应用的资源协议，桌面与移动共用一份 spec。

## 本端原生渲染器（sidecar）

- 位置：`renderer/sidecar.py`（入口）+ 复用 `renderer/render.py`（同一份渲染逻辑）
- 形态：PyInstaller **onedir** 冻结（原生 CPython + numpy/pandas/matplotlib），常驻单进程
- 协议：stdin/stdout 定长帧，二进制安全
  - 请求 `[uint32 LE 长度][UTF-8 JSON {op, spec}]`
  - 响应 `[uint8 状态][uint32 LE 长度][载荷]`（0=成功，1=失败，载荷为错误信息）
  - **stdout 专供协议**：sidecar 启动时把 `sys.stdout` 改道到 stderr，避免第三方库的 print 污染帧流
- 选项：`op ∈ {info, render_png, render_svg, case_script, package_zip}`

Rust 侧（`src-tauri/src/renderer.rs`）负责进程管理与路径解析：

1. 常驻进程，崩溃后下次调用自动重启，单次调用失败重试一次
2. 可执行文件按优先级查找：`MENSIC_RENDER_BIN` 覆盖 → 资源目录 → 可执行文件同级 → 开发期 `src-tauri/binaries/`
3. 退出应用时结束 sidecar，避免残留进程

### 构建

```bash
npm run build:renderer     # 产出 src-tauri/binaries/mensic-render/mensic-render[.exe]
```

会建 `.renderer-venv` 并按**与 Pyodide 对齐的版本**安装依赖（`matplotlib==3.10.8 numpy==2.4.6
pandas==3.0.2 pyyaml==6.0.3`），若某版本不可用则退回最新版（两端版本可能不一致，会放大跨后端的
像素差异）。

依赖用 `--hidden-import` 显式声明（PyInstaller 自带 pandas/numpy/matplotlib 的 hook 会收集 C 扩展与
数据文件），并排除 `tkinter`/Tcl-Tk 与 Pillow 的 AVIF 插件：冻结目录约 **102 MB / 1038 文件**。
（对比：改用 `--collect-all` 会把整包测试套件也收进来，体积 169 MB / 4668 文件。）
产物较大且不入库，`.gitignore` 已排除。

> 构建时请先停掉 `tauri dev`：它会监视 `src-tauri/`，往 `binaries/` 写上千个文件会触发反复重建。

**开发时免打包**（用系统 Python 直接跑 sidecar，改 Python 代码即时生效）：

```powershell
$env:MENSIC_RENDER_BIN="C:\...\python.exe"
$env:MENSIC_RENDER_ARGS="<仓库>/app/renderer/sidecar.py"
npm run tauri dev
```

### 一致性

- 原生后端与 Pyodide **执行同一份 `render.py`**；`run.py` 由渲染器读自身源码的
  `SHARED-RUNTIME` 区块内联，所以导出脚本与预览同源。
- **预览 vs 导出 `run.py`：同一解释器环境下逐字节相同**（已验证：`area-3d-layered`
  两次输出均为 162,875 字节）。
- **跨后端（原生 vs Pyodide/wasm）：无法做到字节一致**，因为 freetype 编译目标不同，
  字形栅格化必然有细微差别。用「版本对齐」把差异压到很小（`area-3d-layered`，同一 spec）：

  | 组合 | 平均通道差 | 不同像素占比 |
  |---|---|---|
  | matplotlib 3.10.8（冻结） vs 3.10.8（Pyodide）— **已对齐** | **0.014 / 255** | **0.071 %** |
  | matplotlib 3.11.1（系统 Python） vs 3.10.8（Pyodide） | 0.228 / 255 | 0.537 % |

  差异全部集中在**文字抗锯齿**上（差异图显示只有刻度/标签的字形轮廓，图形几何完全重合）。
  这正是构建脚本要按 Pyodide 版本 pin 依赖的原因。

### 实测（Windows，本机，`area-3d-layered`）

| 指标 | Pyodide | 本端原生（冻结产物） |
|---|---|---|
| 冷启（含 import） | ~8600 ms | **~1900 ms** |
| 单次渲染 | ~200–270 ms（Python 侧） | **105–181 ms** |
| 内存 | wasm 堆 200–400 MB（在 WebView 内） | 独立进程，不占 WebView |
| 打包体积 | `public/pyodide/` ≈ 45 MB（随前端资源） | 冻结目录 ≈ 102 MB |

> 注意：`import pandas`(3.2s) + `import matplotlib`(2.3s) 是 Pyodide 冷启的主要成本，属于
> in-browser CPython 的固有开销；原生后端把这两项降到 <1s（其中约 0.8s 是本机系统 Python
> 实测值，冻结产物因需初始化 PyInstaller 运行时约 1.9s，仍远低于 Pyodide）。

### Android 环境安装（本机实测可用）

本机原本完全没有 Java/SDK/NDK。以下步骤已在 Windows 上跑通（**注意 `sdkmanager` 的包名**）：

```powershell
$TOOLS = "$env:LOCALAPPDATA\Android"; $SDK = "$TOOLS\Sdk"

# 1) JDK 17。
#    注意：Adoptium 的下载会 302 到 GitHub release assets，本机 DNS 解析不到该域名；
#    改用 Microsoft Build of OpenJDK（download.visualstudio.microsoft.com 可达）。
curl.exe -L -o "$TOOLS\jdk17.zip" "https://aka.ms/download-jdk/microsoft-jdk-17-windows-x64.zip"
tar -xf "$TOOLS\jdk17.zip" -C "$TOOLS"      # 解压后重命名为 jdk-17

# 2) Android 命令行工具
curl.exe -L -o "$TOOLS\cmdline-tools.zip" `
  "https://dl.google.com/android/repository/commandlinetools-win-13114758_latest.zip"
tar -xf "$TOOLS\cmdline-tools.zip" -C "$SDK\cmdline-tools\latest" --strip-components=1

# 3) 组件。compileSdk 37 对应的是 platforms;android-37.0（不是 android-37）
sdkmanager --licenses
sdkmanager "platform-tools" "platforms;android-37.0" "build-tools;37.0.0" "ndk;27.0.12077973"

# 4) Rust 交叉编译目标
rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android

# 5) 环境变量（写入用户级，后续会话生效）
JAVA_HOME=$TOOLS\jdk-17
ANDROID_HOME=$SDK
ANDROID_SDK_ROOT=$SDK
NDK_HOME=$SDK\ndk\27.0.12077973
PATH += $TOOLS\jdk-17\bin; $SDK\cmdline-tools\latest\bin; $SDK\platform-tools
```

模板固定：**AGP 9.3.1 + Gradle 9.6.1 + Kotlin 2.2.10**，`compileSdk/targetSdk = 37`、`minSdk = 24`。

```powershell
npm run tauri android init                                   # 生成 src-tauri/gen/android（应入库）
npm run tauri android build -- --debug --apk --target aarch64 # 调试 APK（真机安装用）
npm run tauri android dev                                    # 需真机/模拟器
```

- 多 ABI：去掉 `--target aarch64`（会为 4 个 ABI 各编译一遍，耗时显著增加）。
- iOS 另需 macOS + Xcode：`npm run tauri ios init`。
- `src-tauri/gen/android` 自带 `.gitignore`，已排除构建产物与 `keystore.properties`。

### 本机的网络限制（很重要）

这台机器对 **github.com / GitHub release assets** 不可达（DNS 解析不了或连接超时），
而多个工具链默认都会跳到 GitHub 取包：

| 组件 | 默认地址 | 现象 | 替代 |
|---|---|---|---|
| JDK | `api.adoptium.net` → `release-assets.githubusercontent.com` | 无法解析 | **Microsoft OpenJDK**（`aka.ms` → `download.visualstudio.microsoft.com`）✅ |
| Gradle 发行包 | `services.gradle.org` → `github.com` | 连接超时 | **腾讯云 / 华为云镜像** ✅ |

Gradle wrapper 下载失败时可以**手工把发行包塞进缓存**（wrapper 只看 zip + `.ok` 标记）：

```powershell
# 缓存目录名是 URL 的哈希，让 wrapper 先失败一次就会创建它
$dir = "$env:USERPROFILE\.gradle\wrapper\dists\gradle-9.6.1-bin\4ticwg1pgcbps2hj28r8so764"
curl.exe -L -o "$dir\gradle-9.6.1-bin.zip" `
  "https://mirrors.cloud.tencent.com/gradle/gradle-9.6.1-bin.zip"
New-Item -ItemType File -Force -Path "$dir\gradle-9.6.1-bin.zip.ok"
```

好消息：**Maven 依赖源都可达**（`repo.maven.apache.org`、`dl.google.com/dl/android/maven2`、
`plugins.gradle.org`），所以依赖解析不受影响。

### Windows 上的坑：符号链接权限

`tauri android build` 在 cargo 编译完成后，会把 `libmensic_lib.so` **软链**到
`app/src/main/jniLibs/<abi>/`。Windows 创建符号链接需要**开发者模式**（或管理员权限），
否则会失败：

```
Failed to create a symbolic link from ... to ...
Creation symbolic link is not allowed for this system.
```

两种解法：

**① 正规做法（推荐，一次设置长期有效）**

开启开发者模式：`设置 → 系统 → 开发者选项 → 开发人员模式`。
或在管理员 PowerShell 里：

```powershell
reg add "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\AppModelUnlock" /t REG_DWORD /f /v AllowDevelopmentWithoutDevLicense /d 1
```

之后 `npm run tauri android build -- --debug --apk` 即可直接使用。

**② 免管理员绕过**（无开发者模式时）

Gradle 里的 rust 任务同样是回头调用 Tauri CLI（所以照样会软链），因此改为**手动放置 .so
并让 Gradle 跳过该任务**：

```powershell
# 1) 先让 Tauri 编出 .so（它会在软链这一步失败，但产物已经生成）
npm run tauri android build -- --debug --apk --target aarch64

# 2) 手动拷贝进 jniLibs（代替软链）
$d = "src-tauri\gen\android"
Copy-Item "src-tauri\target\aarch64-linux-android\debug\libmensic_lib.so" `
          "$d\app\src\main\jniLibs\arm64-v8a\libmensic_lib.so" -Force

# 3) 直接跑 Gradle，排除会触发软链的 rust 任务
cd $d
.\gradlew.bat assembleUniversalDebug `
  -PtargetList=aarch64 -ParchList=arm64 -PabiList=arm64-v8a `
  -x rustBuildUniversalDebug -x rustBuildArm64Debug
```

> 前端不需要另外拷进 `app/src/main/assets/`：tauri-codegen 把 `dist` 编进 `libmensic_lib.so`
> 的 `EmbeddedAssets` 里，WebView 走自定义协议从 `.so` 取（Kotlin 侧的
> `WebViewAssetLoader` 只在 wry 的 `with_asset_loader` 被启用时才生效，Tauri 没用它）。

产物：`app/build/outputs/apk/universal/debug/app-universal-debug.apk`。

**移动端形态（横屏 / 沉浸式 / 首页适配）**：

- **锁定横屏**：`AndroidManifest.xml` 的 MainActivity 写 `android:screenOrientation="sensorLandscape"`（锁横屏、允许重力翻转 180°）。这是桌面形态的数据工作台，竖屏下工具栏放不下。
- **沉浸式全屏**：`MainActivity.goImmersive()` 隐藏状态栏 + 导航栏，滑动可临时唤出、松手自动收起，内容铺进刘海区；`onResume` 再收一次（从后台回来系统会把状态栏放回来）。
- **首页适配**：首页是一张固定尺寸的海报（三张纸 296×330、字标 68px），手机上任一方向都比可视区大，会被裁成「没显示完整」。`Home` 量「可用空间 / 内容自然尺寸」后**只缩不放**地等比缩到放得下 —— 桌面端（够大时）scale 恒为 1，观感零变化。

**发行版（release）**：`app/build.gradle.kts` 已加好 `signingConfigs.release`，当前指向 **Android 自带的调试密钥**（`~/.android/debug.keystore`，别名 `androiddebugkey`，口令都是 `android`）——
好处是能直接装机、且与 debug 包**同签名**（可互相覆盖安装）。但要上架商店、要长期覆盖升级，必须换成你自己的
keystore：生成后把那四行指过去即可（密钥自行保管，丢了就无法再覆盖升级）。
release 会去掉调试符号并压缩，体积显著小于上面的 debug 包。

打包步骤与 debug 完全一样（同样绕开软链），只是 cargo 走 `--release`（编译久、产物小）：

```powershell
npm run tauri android build -- --target aarch64 --apk   # 不写 --debug 就是 release
Copy-Item "src-tauri\target\aarch64-linux-android\release\libmensic_lib.so" `
          "src-tauri\gen\android\app\src\main\jniLibs\arm64-v8a\libmensic_lib.so" -Force
cd src-tauri\gen\android
.\gradlew.bat assembleUniversalRelease `
  -PtargetList=aarch64 -ParchList=arm64 -PabiList=arm64-v8a `
  -x rustBuildUniversalRelease -x rustBuildArm64Release
```

产物：`app/build/outputs/apk/universal/release/app-universal-release.apk`。
另外要注意 `public/`（Pyodide 45 MB + 字体 17 MB）会**内嵌进 libmensic_lib.so**，这是移动端包体的主要来源。

### Android 原生渲染器（Chaquopy）

Pyodide 在手机上要付「wasm 编译 + CPython 解释执行」的代价，冷启动可达数十秒。因此安卓改用
**进程内原生 CPython**（[Chaquopy](https://chaquo.com/chaquopy/)）：

```
TS: rendererPng(spec)
  → invoke("renderer_call", { op, spec })          ← 前端零改动
  → Rust renderer.rs: platform_call()              ← 桌面走 sidecar，安卓走 JNI
  → android_bridge.rs (JNI) → Kotlin NativeRenderer
  → Chaquopy: Python.getInstance().getModule("mensic_entry").call(op, specJson)
  → mensic_entry → sidecar.OPS[op] → render.py     ← 与桌面/导出**同一份渲染逻辑**
```

为什么用 JNI 而不是 Tauri 移动插件：`renderer_call` / `renderer_info` 这条命令链与注册表的
降级链、能力探测、（反）序列化协议全部可以复用，**前端一行都不用改**。

**关键实现点**

- `sidecar.py` 被两端共用：桌面是独立进程 + stdin/stdout 帧协议；安卓是进程内直接调 `OPS`。
  为此把「stdout 让给协议」的动作从导入期移到了 `main()`（Chaquopy 下 `sys.stdout` 没有 `.buffer`）。
- Android 没有 `/tmp`，而 `sidecar.py` 用 `tempfile.mkdtemp()`：
  `mensic_entry.py` 在导入前把 `TMPDIR`/`tempfile.tempdir` 指向 Chaquopy 提供的 `HOME`。
- Kotlin 在 `MainActivity.onCreate`（Java 线程、class loader 正确）里把 `NativeRenderer::class.java`
  通过 `nativeRegister` 交给 Rust，Rust 缓存为**全局引用**；渲染发生在 tokio 阻塞线程上，
  因此每次调用自行 attach 到 JavaVM（绝不在主线程调用 Chaquopy）。
- **AGP 需要降级**：Chaquopy 17 支持 AGP 7.3–9.2，而 Tauri 模板默认 9.3.1 → `gen/android/build.gradle.kts`
  固定为 **9.2.1**。

**版本代差（Chaquopy 预编译索引的硬限制）**

| | 桌面 sidecar | Android（Chaquopy） |
|---|---|---|
| Python | 3.12.9 | 3.12（与本机构建机一致，也是 pip/pyc 的前提） |
| matplotlib | 3.10.8 | **3.8.2** |
| numpy | 2.4.6 | **1.26.2** |
| pandas | 3.0.2 | **2.1.3** |
| pyyaml | 6.0.3 | 6.0.3 |

cp312 能取到的就是这些（索引里 matplotlib 最高 3.8.2）。要完全对齐只能自建 Android wheel，
代价很高。因此**跨后端像素差异会比桌面/ Pyodide 之间更大**，需要真机做一次金标图比对来量化。

**版本代差的实测结论（本机已验证）**

用 Android 的版本组合（mpl 3.8.2 / numpy 1.26.2 / pandas 2.1.3）在 Windows 上建独立 venv，
走真实 sidecar 协议跑了全部 matplotlib 案例：

- **44 个 matplotlib 案例中 43 个通过** —— 版本降级**不破坏任何案例的 API**（单次 65–1006 ms）。
- 唯一失败的 `scatter-classify` 是因为它 `requires: ["scikit-learn"]`，而
  **Chaquopy 索引没有 scikit-learn / scipy 的 cp312 arm64 包** → 该案例由注册表的能力判断
  自动回落到 Pyodide（`nativeSupports()` 已覆盖，无需额外处理）。
- 52 个案例里只有 2 个需要额外依赖（真正非空 `requires` 的只有这 1 个）。

**构建流程**（在「Windows 软链绕过」的基础上，多一步同步 Python 文件）

```powershell
npm run android:sync-python      # 复制 render.py / sidecar.py / 字体到 android/python（生成物，不入库）
npm run tauri android build -- --debug --apk --target aarch64   # 编出 .so（会在软链处失败）
Copy-Item "src-tauri\target\aarch64-linux-android\debug\libmensic_lib.so" `
          "src-tauri\gen\android\app\src\main\jniLibs\arm64-v8a\" -Force
cd src-tauri\gen\android
.\gradlew.bat assembleUniversalDebug -PtargetList=aarch64 -ParchList=arm64 -PabiList=arm64-v8a `
  -x rustBuildUniversalDebug -x rustBuildArm64Debug
```

Chaquopy 会在**配置阶段**用构建机 Python 跑 pip（从此机可达的 `chaquo.com` 拉 Android wheel），
并把 CPython 运行时与这些包按 ABI 打进 APK —— 包体会明显增大（每个 ABI 约 +80–120 MB）。

## 排障

- **界面底部显示 `matplotlib · Pyodide`**：说明本端原生未启用。看应用日志里的
  `[mensic] 本端原生渲染器不可用，回退到 Pyodide：` 提示。
- **`未找到本端原生渲染器可执行文件`**：还没跑 `npm run build:renderer`，或用上面的
  `MENSIC_RENDER_BIN` 走系统 Python。
- **sidecar 报错**：错误信息会带完整 traceback 回传并显示在编辑器里；sidecar 自身的
  启动日志走 stderr，由 Rust 侧转发到应用日志（前缀 `[mensic-render]`）。
