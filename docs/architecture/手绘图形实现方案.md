# 手绘图形实现方案（mensic 纸质笔记风）

> 本文档记录当前 App 里"手绘/铅笔/纸质笔记"图形的**完整技术方案**，供后续制作风格一致的新图形时复用。
> 核心：**rough.js 的 `hachure` 排线填充** + **淡色打底** + **噪点遮罩** + **撕纸 clip-path**；运行时全部**烘焙到 canvas** 以保性能。

---

## 1. 依赖与总原则

- 手绘渲染库：**`roughjs`**（Excalidraw 同款）。它给几何形状加"手抖"并可用排线填充。
- 关键填充风格：`fillStyle: "hachure"` → 铅笔排线；配合一层 `fillStyle: "solid"` 淡色打底 → 参考图那种"淡色 + 排线"的手绘感。
- **性能原则**：所有**静态**手绘图形都**烘焙成位图（canvas）**，只在尺寸变化时重绘一次；不要用 `feTurbulence` / `feDisplacementMap` 这类运行时滤镜（开销极大）。

---

## 2. 核心配方：`fill2`（淡色打底 + 铅笔排线）

每个图形画**两遍**（`src/components/rough.tsx`）：

```ts
// 1) 淡色打底
make({ fill: rgba(color, 0.30), fillStyle: "solid",   stroke: "none", roughness: 1.2, bowing: 1.1, seed });
// 2) 铅笔排线
make({ fill: rgba(color, 0.60), fillStyle: "hachure", hachureAngle: angle, hachureGap: gap,
       stroke: "none", roughness: 1.5, bowing: 1.3, seed: seed + 1 });
```

- `make` 接收 rough 选项并绘制一个形状：`(o) => rc.path(d, o)` / `(o) => rc.circle(cx, cy, d, o)` / `(o) => rc.polygon(points, o)`。
- `rc` 是 `rough.canvas(canvas)`（烘焙版）或 `rough.svg(svg)`（小尺寸直接 SVG）。
- 参数含义：
  - `hachureAngle`：排线角度，统一用 **-41**（约 -45°，45° 斜排线观感）。
  - `hachureGap`：排线间距，**越小越密**。大图形 6，中等 4~5，小球 3~4。
  - `roughness`（手抖幅度）、`bowing`（线弯曲）控制"手绘感"强弱；越大越随意。
  - `seed`：固定随机种子 → 每次渲染形状一致（重要：避免抖动/闪烁）。

## 4. 铅笔"若隐若现"质感（噪点瓦片）

网格线那种"忽深忽浅、时密时连"的铅笔感，**不要**用 SVG `feTurbulence` 滤镜（运行时开销巨大）。

做法（`src/components/baked.tsx`）：
1. `makeNoise(size, baseCells, octaves, gain, seed)`：程序化生成**分形值噪声**瓦片，像素 alpha = 噪声强度（`rgba(0,0,0,alpha)`）。
2. `getNoiseTiles()` 生成**两块并缓存**：**粗斑**（低频，`baseCells 3`）+ **细密颗粒**（高频，`baseCells 26`）；在 App 启动后 ~400ms 空闲时预热。
3. 绘制网格线时：先画线，再用 `globalCompositeOperation = "destination-out"` 依次 `fillRect` 两块噪点瓦片（`createPattern(..., "repeat")`）→ 擦出断续效果。

> 两块叠加 ≈ 原来两层 `feTurbulence` 遮罩的乘积效果，但运行时零滤镜开销。

## 5. 撕纸边缘（paper-torn）

卡片/纸片的"撕边"是 **SVG `<path>` 填色**，投影是 **CSS `filter: drop-shadow`**（`src/components/ui/paper.tsx`）：

- 顶点由 `ui/torn.ts` 的 `tornClipPath(seed)` / `tornPoints(seed)` 生成（LCG，段数 10–14、抖动 1.3%–2.4% 都由种子决定）；
  种子 = 卡片 id（案例 / 项目 / 文件夹），所以**每张卡毛边不同、同一张永远同一形状**（模块内缓存，重渲染零成本）。
- `viewBox="0 0 1 1"` + `preserveAspectRatio="none"` → 等价于 objectBoundingBox，一套路径自适应任意卡片尺寸。
- ⚠️ **盒子必须 `inset-0`（不溢出）**，投影只由 `filter` 画到盒子外面 —— 原因见下。

**⚠️ 不要用 `clip-path: url(#…)` 做撕边**（实测）：`filter: drop-shadow` 的元素里再套一个 URL 引用的 clip-path，
会让 Blink 每次挂载做几何映射 + 蒙版合成 → **每卡 ~5.5ms 的 style/layout**（图鉴 10 卡 = 每次打开一个 ~55ms 长帧）。
换成 path 填色即可，画面与投影逐像素一致（投影深度差 ≤ 0.15/255）。

**⚠️ 也不要烘焙成 `<canvas>` 位图**（试过两次，两次都全面变差）：
1. 投影会溢出纸面 ~31px，画布就得向外扩 —— 而创作页瀑布流是 CSS `columns`，Chromium 有一条硬规则：
   **脱离文档流、且溢出 multicol 子元素的盒子，其包含块会被提升为「分片容器」（整个 multicol 容器）**。
   实测：卡片 355×293，纸层却按容器变成 803×644、偏移 -413 —— 除第一张卡外纸层全部错位；
   `contain: layout / paint / content`、`isolation` 都拦不住这条规则。
2. 就算改回不溢出（画布 `inset-0`、投影交给外层 filter），**帧率反而更差**：
   同一页图鉴，SVG 路径版 **162 FPS / 0 长帧**，canvas 版只有 **29 FPS / 11 个长帧**。

想让投影也不再走 filter，前提是把创作页瀑布流从 CSS `columns` 换成 flex/grid 分栏（那是另一件事）。

**抬起（悬停）态**：`raised` 切到更强的那套 filter，靠 `transition-[filter]` 过渡（300ms）。

**⚠️ 投影只允许两条 `drop-shadow`**（实测：图鉴切分类，阻塞时长 = 超出 60Hz 帧预算的部分）：

| 投影条数 | 切分类 ×4 的阻塞 | >20ms 的单帧 | 单次切分类（图已缓存） |
|---|---|---|---|
| 3 条（原样：光晕 + 接触 + 环境） | ≈350ms | 45~49 个 | ≈225ms |
| 2 条（光晕 + 合并后的下沉投影） | **≈50ms** | **0 个** | **4~79ms** |
| 0 条（下界） | ≈0 | 0 个 | — |

根因：**链式 `filter` 的输入是上一条的输出**（已经模糊过、更大的面），成本滚着涨、不是线性叠加；
「详情 ↔ 列表」的卡顿同理（纸张重新光栅化 ≈80~300ms → 4~58ms）。
原第 2/3 条（接触 `0 2px 4px .033` + 环境 `0 5px 8px .053`）用 1D 高斯复合做最小二乘拟合，
等价于**一条** `0 3.5px 7px .085`（最大误差 0.78/255；悬停那套同理 → `0 6.5px 14px .128`，1.04/255）。
同场景截图像素差：**最大 3/255、均值 0.08/255、≥4/255 的像素 0 个**（肉眼不可分）。
**要再调投影，照这个办法拟合，别再往上加条数。**

**压在纸上的层**（选中掩膜、高亮）走 SVG，但必须用**同一条路径**：`selected` 用 `tornClipPath`
填底色 + 描边，描边是 SVG `non-scaling-stroke`（`viewBox="0 0 1 1"` + `preserveAspectRatio="none"` 会把线宽非等比拉伸）。

边缘只**往里凹**（不往外凸），所以卡片外框就是毛边最外沿；凹陷幅度上限 2.4% 是照着卡片内容
最小的内边距（~10px）定的 —— 超过就会啃到图，加新卡片时注意。

## 6. 烘焙到 canvas（性能关键）

`useBakedCanvas(draw, deps)`（`src/components/baked.tsx`）：
- 用 `ResizeObserver` 的 `contentRect` 测尺寸（**不受 transform 影响**，hover/切页动画不会触发重绘）。
- 只在 `[size.w, size.h, ...deps]` 变化时：设置 DPR、`ctx.setTransform(dpr,…)`、清屏、调用 `draw(ctx, rough.canvas(canvas), w, h)`。
- 结果是**一张位图**：动画/滚动时浏览器无需重新光栅化大量矢量路径与滤镜。

**为什么**：优化前一次「主页→画廊」切换 `RasterTask ≈ 1150ms`（掉帧主因）；烘焙 + 去滤镜后降到 `≈ 300ms`，切换接近满帧。

## 8. 新增一个"同类手绘图形"的步骤

1. 确定它是**大图形还是小装饰**：
   - 大/复杂 → 用 `useBakedCanvas` 烘焙到 canvas。
   - 小（≤ ~64px 或简单几笔）→ 直接 `rough.svg(svg)`。
2. 用 `fill2` 画"淡色打底 + 排线"；线条类直接 `rc.line/curve`（给 `stroke`、`strokeWidth`、`roughness`、`bowing`、`seed`）。
3. 颜色取第 7 节色板；排线角度统一 -41，间距按大小取 3~6。
4. **固定 `seed`**（保证不闪）。
5. 若要铅笔断续感 → 叠加噪点瓦片擦除（第 4 节）。
6. 若要纸片/撕边 → 用 `<PaperLayers seed={id} />`（每张卡自己的毛边；首页那套统一形状的不传 seed），见第 5 节。
7. **不要**引入 `feTurbulence`/`feDisplacementMap` 运行时滤镜。

## 9. 空间与后续可扩展

- 可继续扩展的形状：小人、图表轮廓、标注圈（rough-notation 风格）、贴纸、书签等，套用同一配方即可。
- 若某手绘图形需要在运行时动态变化（如随数据变化的笔触），可对**变化的部分**单独重绘，静态部分仍用烘焙 bitmap 叠加。
